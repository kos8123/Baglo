# Baglo開發難題與解法

本文件只記錄產品與系統開發期間實際發現的問題，依照「發現問題 → 原因 → 解法」整理。

## 資料存取與效能

### 跨網域API無法存取

- **發現問題：** 部署前端後，瀏覽器Console顯示API Gateway回應缺少`Access-Control-Allow-Origin`，`/api/config`無法讀取。
- **發生原因：** 新的前端網域未包含在後端允許的origins，瀏覽器的CORS preflight因此遭拒絕。
- **解法：** 將實際前端origin納入API Gateway／Lambda CORS設定，並把匿名行情路由與Cognito JWT保護的帳戶路由分開。

### K線第一次載入超過十秒

- **發現問題：** 切換股票或重新整理時，K線長時間停在載入狀態；資料範圍越長越明顯。
- **發生原因：** 每次請求都即時向上游取得大量歷史資料並重新聚合日、週、月K線，速度同時受上游延遲與請求限制影響。
- **解法：** 預先整理日、週、月K線並存入R2。Pages Function優先讀取快取，Market Sync Worker負責歷史回填及收盤後增量更新。

### 部分股票沒有完整歷史資料

- **發現問題：** AI選出的部分股票只顯示代號，K線與回測欄位出現「歷史資料有缺漏」；TPEx API也曾回報Too many redirects。
- **發生原因：** 上游來源可能重複導向或暫時失效；候選池也可能包含上市時間較短、流動性不足或OHLCV不完整的標的。
- **解法：** 加入timeout、來源驗證與fallback。AI選股前先驗證代號、名稱、流動性及歷史資料長度，不符合最低資料品質的股票直接略過並顯示原因。

## 前端狀態與交易體驗

### 已選股票與下單狀態不一致

- **發現問題：** 搜尋到台積電後，下單區仍提示需要先搜尋；部分成功委託也被畫面顯示為失敗。
- **發生原因：** 搜尋結果、目前標的與下單表單分別保存狀態，非同步請求完成後仍可能讀到舊值；前端對成功回應的判定格式也不一致。
- **解法：** 將頁面遷移到React共用狀態，以TanStack Query管理伺服器資料，統一委託成功條件，並使用idempotency key防止重複下單。

### 重新整理後自選股與AI候選股消失

- **發現問題：** 使用者加入自選股或完成AI選股後，重新整理頁面就看不到原本內容。
- **發生原因：** 自選股、AI設定與候選結果只存在前端記憶體，沒有以使用者身分寫入後端資料庫。
- **解法：** 以Cognito user sub區分帳戶，將自選股、AI設定、候選股及執行狀態保存至DynamoDB，頁面載入時重新查詢。

## 身分與權限

### 訪客看盤與會員功能互相衝突

- **發現問題：** 原本未登入時會直接進入登入流程，無法達成「訪客可以看盤、登入後才能交易」的需求。
- **發生原因：** 頁面與API最初將所有功能視為同一種驗證層級，沒有區分公開市場資料與使用者帳戶資料。
- **解法：** 訪客開放標的搜尋、價格與K線；帳戶、持倉、委託、自選股及AI功能使用Cognito JWT保護。Email登入、Google OAuth與PKCE統一交由Cognito處理。
